# Research Pre-Mortem

## Purpose

This file records early red-team critique before a research direction is frozen.

Use it to identify why the project might fail before implementation begins.

A pre-mortem is not a rejection by default. It is a structured attempt to expose weak assumptions, novelty risks, missing baselines, evaluation problems, and likely reviewer objections early.

## Status

- Status: `draft`
- Allowed values: `draft`, `completed`, `superseded`
- Project-specific pre-mortem recorded: `no`

## Pre-Mortem Rule

Do not freeze a high-impact research direction without checking whether a pre-mortem is needed.

A pre-mortem is required when:

- novelty is uncertain;
- closest prior work is strong;
- baseline or metric is unclear;
- publication-worthiness is uncertain;
- the method depends on a fragile assumption;
- the evaluation path is expensive;
- the user is about to commit to implementation.
